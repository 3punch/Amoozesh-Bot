# ربات دستیار انتخاب واحد (Amoozesh Bot)

ربات تلگرامی که به سوالات دانشجویان درباره‌ی **چارت درسی**، **اساتید**، **لیست دروس ارائه‌شده** و
**محدودیت ورودی‌ها** جواب می‌دهد.

نسخه‌ی فعلی به‌جای هر API ابری، از **مدل محلی Gemma 3 با Ollama** استفاده می‌کند؛
یعنی **هیچ API key ای لازم نیست** (نه OpenRouter، نه OpenAI، نه هیچ‌جای دیگر).

```
سوال کاربر
   ↓
retrieval.py   ← فقط بخش‌های مرتبط دیتا را انتخاب می‌کند (~۲–۳ هزار توکن)
   ↓              + حکم قطعی «مجاز بودن درس» را از knowledge_base.txt محاسبه می‌کند
prompts.py     ← پرامپت کوتاه و قاعده‌محور مناسب مدل کوچک
   ↓
llm.py         ← POST به Ollama محلی (gemma3:4b)
   ↓
پاسخ فارسی کوتاه در تلگرام
```

---

## ۱) اجرا روی سیستم خودت (پیشنهادی)

```bash
# نصب Ollama (لینوکس/مک)
curl -fsSL https://ollama.com/install.sh | sh      # ویندوز: نصب‌کننده از ollama.com

# در یک ترمینال: سرور مدل
ollama serve

# در ترمینال دیگر: دانلود مدل (~۳.۳ گیگ، یک بار)
ollama pull gemma3:4b

# نصب پکیج‌های پایتون و اجرای ربات
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN="توکن-ربات-خودت"
python EntekhabVahedBot.py
```

سپس در تلگرام به ربات `/start` بده.

> **بدون اینترنت یا روی سیستم ضعیف:** می‌توانی مدل کوچک‌تر بگیری:
> ```bash
> ollama pull gemma3:1b
> MODEL_NAME=gemma3:1b python EntekhabVahedBot.py
> ```
> کیفیت فارسی ۱B به‌طور محسوس پایین‌تر است (به‌خصوص در جمع‌بندی نظرات).

### اجرای دائمی با systemd (VPS)

```ini
# /etc/systemd/system/amoozeshbot.service
[Unit]
Description=Amoozesh Telegram Bot
After=network-online.target ollama.service

[Service]
WorkingDirectory=/opt/Amoozesh-Bot
Environment=TELEGRAM_BOT_TOKEN=توکن
Environment=MODEL_NAME=gemma3:4b
ExecStart=/usr/bin/python3 /opt/Amoozesh-Bot/EntekhabVahedBot.py
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now amoozeshbot
```

## ۲) اجرا روی GitHub Actions

ورک‌فلوی `.github/workflows/bot.yml` این کارها را انجام می‌دهد:
نصب Ollama → کش کردن وزن‌های مدل با `actions/cache` → `ollama pull gemma3:4b` →
اجرای تست‌ها → اجرای ربات به‌مدت حداکثر ۶ ساعت.

فقط یک Secret لازم است:

| نام Secret | مقدار |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن ربات از @BotFather |

⚠️ **محدودیت‌های واقعی Actions** (لطفاً قبل از تکیه بر این روش بخوان):
- هر run حداکثر ۶ ساعت زنده است؛ cron هر ۶ ساعت یک run جدید می‌سازد، اما در فاصله‌ی
  بین مرگ یک run و شروع بعدی ربات خاموش است.
- بار اول مدل دانلود می‌شود (کش بعد از اولین بار کمک می‌کند، ولی کش‌های Actions بعد از
  ۷ روز بدون استفاده پاک می‌شوند).
- رانر ۱۶ گیگ رم دارد؛ `gemma3:4b` راحت جا می‌شود.
- مصرف دقیقه‌های Actions زیاد است (~۲۴ ساعت در روز = بیشتر از سهمیه‌ی رایگان).
  برای استفاده‌ی واقعی، یک VPS ۸ گیگی یا self-hosted runner بهتر و ارزان‌تر است.
- `concurrency` تنظیم شده تا دو نمونه همزمان روی `getUpdates` تلگرام تداخل نکنند.

## ۳) متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | **الزامی** |
| `MODEL_NAME` | `gemma3:4b` | نام مدل در Ollama |
| `OLLAMA_HOST` | `http://127.0.0.1:11434` | آدرس سرویس Ollama |
| `NUM_CTX` | `8192` | پنجره‌ی زمینه |
| `MAX_TOKENS` | `320` | حداکثر طول پاسخ |
| `TEMPERATURE` | `0.2` | مقدار پایین = پاسخ‌های ثابت‌تر |
| `LLM_TIMEOUT` | `300` | مهلت هر درخواست (ثانیه) |
| `OLLAMA_KEEP_ALIVE` | `6h` | مدل چقدر در RAM بماند |
| `MAX_CONTEXT_CHARS` | `9000` | سقف متن زمینه |
| `MAX_PROFESSOR_BLOCKS` | `3` | حداکثر شناسنامه‌ی استاد در هر پاسخ |
| `MAX_COURSE_ROWS` | `8` | حداکثر ردیف درس در هر پاسخ |

## ۴) ساختار فایل‌ها

| فایل | نقش |
|---|---|
| `EntekhabVahedBot.py` | نقطه‌ی ورود؛ هندلر تلگرام، مدیریت گروه، شکستن پیام‌های بلند |
| `llm.py` | کلاینت Ollama (پیش‌بارگذاری مدل، تشخیص نصب‌بودن، مدیریت خطا) |
| `retrieval.py` | نرمال‌سازی فارسی، انتخاب بخش‌های مرتبط، حکم قطعی مجاز بودن درس |
| `prompts.py` | پرامپت سیستم و پیام‌های ثابت |
| `ask.py` | پرسش مستقیم از خط فرمان (بدون تلگرام) برای تست سریع |
| `tests/test_offline.py` | تست بدون نیاز به مدل و تلگرام (سرور جعلی Ollama) |
| `extract.py` | (ابزاری) ساخت `professors.txt` از فایل‌های JSON خروجی تلگرام |

### دیتای پروژه
- `courses.xlsx` — جدول ارائه دروس این ترم
- `professors.txt` — ۳۵ شناسنامه‌ی استاد با نظرات دانشجویان
- `knowledge_base.txt` — قوانین محدودیت ورودی‌ها
- `curriculum.pdf` — چارت درسی

## ۵) تست

```bash
python tests/test_offline.py          # بدون مدل و بدون تلگرام
python retrieval.py                   # بررسی اندازه‌ی زمینه برای چند سوال نمونه

# پرسش واقعی از مدل، بدون تلگرام (سریع‌ترین راه دیدن خروجی)
python ask.py "استاد آذر ابوالقاسمی چطور استادی هستن"
python ask.py --context "بهینه سازی خطی برای ورودی ۱۴۰۳ مجازه؟"   # فقط زمینه
python ask.py --json "ساختمان داده و الگوریتم ها با همامی"
```

## ۶) تغییرات نسبت به نسخه‌ی قبلی

| قبل | بعد |
|---|---|
| `requests.post` به `openrouter.ai` با `OPENROUTER_API_KEY` | مدل محلی Ollama، بدون هیچ کلیدی |
| کل دیتا (~۱۸۰ هزار کاراکتر) داخل پرامپت | فقط بخش‌های مرتبط (~۲–۳ هزار توکن) |
| باگ: `professors.txt` با `---` اسپلیت می‌شد ولی با `===` ساخته شده بود ⇒ همیشه کل فایل می‌رفت | تقسیم درست بر اساس «شناسنامه استاد» + رتبه‌بندی و سقف ۳ بلوک |
| نظرات شامل فهرست لینک گروه‌ها و تبلیغ کانال بود | حذف پیام‌های لینکی/تبلیغی و مرتب‌سازی نظرات تا ارزیابی واقعی بالا بیاید |
| قوانین ورودی‌ها همیشه در پرامپت بود | فقط برای سوال‌های مربوط به ورودی/مجاز بودن (صرفه‌جویی ~۶۰۰ توکن) |
| مجاز بودن درس‌ها کاملاً به مدل سپرده شده بود | یک بررسی قطعی (rule-based) روی `knowledge_base.txt` که پاسخ درست را به مدل می‌دهد |
| خطای مدل ⇒ پیام مبهم «پرامپت دیگری وارد کنید» | پیام مشخص + لاگ + تشخیص مدل نصب‌نشده |
| بدون تست، بدون پشتیبانی از /start | تست آفلاین، `/start`، شکستن پیام‌های >۴۰۹۶ کاراکتر، جلوگیری از تداخل در گروه |

## ۷) محدودیت‌های شناخته‌شده

- مدل ۴B فارسی را «قابل‌قبول» می‌نویسد، ولی گاهی جمله‌بندی ضعیف یا اطلاعات را ناقص
  جمع‌بندی می‌کند. برای همین پاسخ‌ها کوتاه و مستقیماً از زمینه ساخته می‌شوند.
- جست‌وجو کلیدواژه‌ای است (بدون embedding)؛ سوال‌هایی با غلط املایی یا نام مستعار
  ممکن است بخش مرتبط را پیدا نکنند.
- اگر سوالی خارج از دیتا باشد، مدل موظف است بگوید «این مورد در اطلاعات موجود نیست».
