# ربات دستیار انتخاب واحد (Amoozesh Bot)

ربات تلگرامی که به سوالات دانشجویان درباره‌ی **چارت درسی**، **اساتید**، **لیست دروس ارائه‌شده** و
**محدودیت ورودی‌ها** جواب می‌دهد.

نسخه‌ی فعلی به‌جای هر API ابری، از **مدل محلی Qwen با Ollama** استفاده می‌کند؛
یعنی **هیچ API key ای لازم نیست** (نه OpenRouter، نه OpenAI، نه هیچ‌جای دیگر).

```
سوال کاربر
   ↓
retrieval.py   ← فقط بخش‌های مرتبط دیتا را انتخاب می‌کند (~۲–۳ هزار توکن)
   ↓              + حکم قطعی «مجاز بودن درس» را از knowledge_base.txt محاسبه می‌کند
prompts.py     ← پرامپت کوتاه و قاعده‌محور مناسب مدل کوچک
   ↓
fallback.py    ← اگر مدل نبود/خطا داد: پاسخ قطعی از خود دیتا (ربات ساکت نمی‌ماند)
   ↓
llm.py         ← POST به Ollama محلی (qwen2.5:7b)
   ↓
پاسخ فارسی کوتاه در تلگرام
```

## ۱) اجرا — همه‌چیز داخل GitHub Actions

> هیچ چیزی لازم نیست روی سیستم خودت نصب یا روشن باشد؛ نه Ollama، نه پایتون.
> کل زنجیره (نصب Ollama → دانلود مدل → اجرای ربات) داخل runner گیت‌هاب انجام می‌شود.

**تنها کار لازم:** یک Secret در مخزن.

1. `Settings → Secrets and variables → Actions → New repository secret`
2. نام: `TELEGRAM_BOT_TOKEN` — مقدار: توکن ربات از @BotFather
3. برو به تب **Actions** → workflow **Run Telegram Bot 24/7** → **Run workflow**

از این به بعد خودکار اجرا می‌شود: هر ۵ ساعت یک run در صف می‌گذارد و هر نمونه
۵ ساعت و ۲۰ دقیقه کار می‌کند؛ نمونه‌ی بعدی بلافاصله جایش را می‌گیرد.

### چرخه‌ی کار (چرا همیشه روشن می‌ماند)

```
cron هر ۵ ساعت ──► run در صف ──┐
                                │  concurrency: فقط یکی هم‌زمان
run فعال (۵:۲۰ کار) ────────────┘
   ├─ کرش کرد؟  → scripts/run_bot.sh بلافاصله دوباره بالا می‌آورد
   ├─ ۵:۲۰ شد؟  → خاموشی تمیز، run صف‌شده فوراً شروع می‌شود
   └─ روی main کامیت جدید آمد؟ → خودش خارج می‌شود تا کد تازه فعال شود
```

- **نصب Ollama و دانلود مدل** فقط بار اول کند است؛ وزن‌ها با `actions:cache` کش
  می‌شوند و در runهای بعدی ~۱ دقیقه است.
- مخزن **عمومی** است ⇒ دقیقه‌های Actions **رایگان و نامحدود**.

### تست کیفیت مدل (بدون تلگرام)

تب **Actions** → workflow **Test Model Quality** → **Run workflow**.
می‌توانی در فیلد `question` سوال خودت را بنویسی (پیش‌فرض `gemma3:12b`).
نتیجه در فایل `reports/model-report.md` کامیت می‌شود و همیشه در مخزن قابل
مشاهده است: پاسخ قطعی ربات، جمع‌بندی مدل و دلیل رد‌شدن آن (اگر رد شود).

آخرین نتیجه‌ی واقعی (۴ سوال نمونه، `gemma3:12b`): هر ۴ پاسخ درست و بدون
توهم زمان/عدد بود. با `gemma3:4b` مدل در ۲ مورد از ۴ مورد ساعت ساختگی یا
ادعای غلط تولید کرد؛ به همین دلیل پاسخ قطعی همیشه اول ارسال می‌شود و
جمع‌بندی مدل فقط پس از اعتبارسنجی ضمیمه می‌شود.

### بنچمارک مدل‌ها (اندازه‌گیری واقعی روی runner)

Actions → **Benchmark Models** → Run workflow (مثلاً `qwen2.5:7b,qwen3:8b,qwen3:4b,gemma3:4b`).
گزارش در `reports/model-bench.md` کامیت می‌شود.

نتیجه‌ی اندازه‌گیری‌شده (۴ سوال واقعی، runner دو‌هسته‌ای گیت‌هاب، `MAX_TOKENS=160`):

| مدل | میانگین زمان پاسخ | سرعت | جمع‌بندی درست |
|---|---|---|---|
| `qwen3:4b` | ۱۲۳ث | ۵.۸ tok/s | ۳ از ۴ (و استدلال انگلیسی تولید کرد) |
| `qwen2.5:7b` | ۱۷۳ث | ۴.۴ tok/s | ۴ از ۴ «تأیید» ولی ۲ مورد از نظر معنایی غلط |
| `qwen3:8b` | ۱۸۶ث | ۳.۹ tok/s | ۴ از ۴ «تأیید» ولی ۱ مورد زمان را جابه‌جا گفت |
| `gemma3:12b` (قبلی) | ~۳۰۰ث | ~۲ tok/s | ۴ از ۴، بدون توهم عددی |

**نتیجه‌ی مهم:** گلوگاه، خانواده‌ی مدل نیست؛ **CPU رانر** است. حتی ۴B هم روی
CPU کند است و هیچ مدلی در این اندازه قابل‌اعتماد نیست. بنابراین:

- پاسخ کاربر از موتور قطعی (`fallback.py`) می‌آید: **فوری، دقیق، بدون توهم**
- مدل فقط اگر `MODEL_SUMMARY=1` باشد یک جمع‌بندی کوتاه اضافه می‌کند
- `qwen2.5:7b` پیش‌فرض است: فارسی بهتر از Gemma و بدون حالت استدلال

### محدودیت‌های واقعی این روش

| محدودیت | توضیح |
|---|---|
| سرعت پاسخ مدل | پاسخ قطعی فوری است؛ اگر `MODEL_SUMMARY=1` باشد ۲ تا ۴ دقیقه هم اضافه می‌شود |
| سقف ۶ ساعت هر job | با چرخش خودکار ۵:۲۰ مدیریت شده، ولی در لحظه‌ی تعویض ~۱–۲ دقیقه وقفه هست |
| cron گیت‌هاب دقیق نیست | ممکن است چند دقیقه تأخیر داشته باشد؛ چون همیشه یک run در صف هست، وقفه ایجاد نمی‌کند |
| ربات خاموشیِ طولانی = پیام ازدست‌رفته | `drop_pending_updates` فعال است |
| غیرفعالی خودکار | اگر ۶۰ روز هیچ فعالیتی در مخزن نباشد، GitHub workflowهای زمان‌بندی‌شده را خاموش می‌کند؛ با یک push یا Run دستی دوباره فعال می‌شود |
| مصرف منابع | هر run ~۳.۵ گیگ رم و چند گیگ دیسک runner را می‌گیرد (مخزن عمومی = رایگان) |

## ۲) اجرای محلی (اختیاری، برای توسعه)

اگر خواستی روی سیستم خودت تست کنی:

```bash
ollama serve            # یا سرویس systemd
ollama pull gemma3:4b
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN="توکن"
python EntekhabVahedBot.py          # RUN_DURATION_MINUTES=0 ⇒ تا Ctrl+C کار می‌کند

python ask.py "استاد آذر ابوالقاسمی چطور استادی هستن"   # بدون تلگرام
python tests/test_offline.py                            # تست آفلاین
```

## ۳) متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | **الزامی** |
| `MODEL_NAME` | `qwen2.5:7b` | نام مدل در Ollama (`qwen3:4b`، `qwen3:8b`، `gemma3:4b` …) |
| `THINK` | `0` | حالت استدلال Qwen3 (خاموش = سریع‌تر) |
| `OLLAMA_HOST` | `http://127.0.0.1:11434` | آدرس سرویس Ollama |
| `NUM_CTX` | `3072` | پنجره‌ی زمینه |
| `MAX_TOKENS` | `120` | حداکثر طول پاسخ |
| `TEMPERATURE` | `0.2` | مقدار پایین = پاسخ‌های ثابت‌تر |
| `LLM_TIMEOUT` | `300` | مهلت هر درخواست (ثانیه) |
| `OLLAMA_KEEP_ALIVE` | `6h` | مدل چقدر در RAM بماند |
| `MAX_CONTEXT_CHARS` | `4000` | سقف متن زمینه |
| `MAX_PROFESSOR_BLOCKS` | `2` | حداکثر شناسنامه‌ی استاد در هر پاسخ |
| `MAX_COURSE_ROWS` | `5` | حداکثر ردیف درس در هر پاسخ |
| `RUN_DURATION_MINUTES` | `0` | بعد از این مدت خاموشی تمیز؛ `0` = نامحدود |
| `BOT_RUN_MINUTES` | `320` | مدت کار هر نمونه در Actions |
| `BOT_JOB_MINUTES` | `335` | کل عمر job (باید < ۳۶۰ باشد) |
| `CHECK_UPDATES` | `1` | خروج خودکار وقتی روی main کامیت جدید آمد |
| `MODEL_SUMMARY` | `0` | ضمیمه‌کردن جمع‌بندی مدل به پاسخ قطعی (`1` = با مدل) |

## ۴) ساختار فایل‌ها

| فایل | نقش |
|---|---|
| `EntekhabVahedBot.py` | نقطه‌ی ورود؛ هندلر تلگرام، مدیریت گروه، شکستن پیام‌های بلند |
| `llm.py` | کلاینت Ollama (پیش‌بارگذاری مدل، تشخیص نصب‌بودن، مدیریت خطا) |
| `retrieval.py` | نرمال‌سازی فارسی، انتخاب بخش‌های مرتبط، حکم قطعی مجاز بودن درس |
| `prompts.py` | پرامپت سیستم و پیام‌های ثابت |
| `ask.py` | پرسش مستقیم از خط فرمان (بدون تلگرام) برای تست سریع |
| `fallback.py` | پاسخ قطعی بدون مدل (اگر Ollama نبود/خطا داد، ربات ساکت نمی‌ماند) |
| `scripts/run_bot.sh` | نگه‌دارنده: ری‌استارت خودکار + چرخش + تشخیص کامیت جدید |
| `.github/workflows/model-check.yml` | تست کیفیت مدل به‌صورت دستی (بدون تلگرام) |
| `tests/test_offline.py` | تست بدون نیاز به مدل و تلگرام (سرور جعلی Ollama) |
| `extract.py` | (ابزاری) ساخت `professors.txt` از فایل‌های JSON خروجی تلگرام |

### دیتای پروژه
- `courses.xlsx` — جدول ارائه دروس این ترم
- `professors.txt` — ۳۵ شناسنامه‌ی استاد با نظرات دانشجویان
- `knowledge_base.txt` — قوانین محدودیت ورودی‌ها
- `curriculum.pdf` — چارت درسی

## ۶) تغییرات نسبت به نسخه‌ی قبلی

| قبل | بعد |
|---|---|
| `requests.post` به `openrouter.ai` با `OPENROUTER_API_KEY` | مدل محلی Ollama، بدون هیچ کلیدی |
| کل دیتا (~۱۸۰ هزار کاراکتر) داخل پرامپت | فقط بخش‌های مرتبط (~۲–۳ هزار توکن) |
| باگ: `professors.txt` با `---` اسپلیت می‌شد ولی با `===` ساخته شده بود ⇒ همیشه کل فایل می‌رفت | تقسیم درست بر اساس «شناسنامه استاد» + رتبه‌بندی و سقف ۳ بلوک |
| نظرات شامل فهرست لینک گروه‌ها و تبلیغ کانال بود | حذف پیام‌های لینکی/تبلیغی و مرتب‌سازی نظرات تا ارزیابی واقعی بالا بیاید |
| قوانین ورودی‌ها همیشه در پرامپت بود | فقط برای سوال‌های مربوط به ورودی/مجاز بودن (صرفه‌جویی ~۶۰۰ توکن) |
| مجاز بودن درس‌ها کاملاً به مدل سپرده شده بود | یک بررسی قطعی (rule-based) روی `knowledge_base.txt` که پاسخ درست را به مدل می‌دهد |
| خطای مدل ⇒ پیام مبهم «پرامپت دیگری وارد کنید» | پاسخ قطعی از خود دیتا (fallback) + لاگ + پیام راهنما |
| اجرا نیاز به سرور/سیستم روشن داشت | کل اجرا در GitHub Actions با چرخش خودکار و بدون توقف |
| بدون تست، بدون پشتیبانی از /start | تست آفلاین، `/start`، شکستن پیام‌های >۴۰۹۶ کاراکتر، جلوگیری از تداخل در گروه |

## ۷) محدودیت‌های شناخته‌شده

- مدل ۴B فارسی را «قابل‌قبول» می‌نویسد، ولی گاهی جمله‌بندی ضعیف یا اطلاعات را ناقص
  جمع‌بندی می‌کند. برای همین پاسخ‌ها کوتاه و مستقیماً از زمینه ساخته می‌شوند.
- جست‌وجو کلیدواژه‌ای است (بدون embedding)؛ سوال‌هایی با غلط املایی یا نام مستعار
  ممکن است بخش مرتبط را پیدا نکنند.
- اگر سوالی خارج از دیتا باشد، مدل موظف است بگوید «این مورد در اطلاعات موجود نیست».
- اگر مدل در دسترس نباشد، پاسخ‌ها از `fallback.py` می‌آیند: دقیق ولی خشک و بدون
  جمع‌بندی زبانی (با برچسب «مدل محلی در دسترس نبود»).
- ورودی‌های غیرمتنی (ویس/عکس/استیکر) پشتیبانی نمی‌شوند.
